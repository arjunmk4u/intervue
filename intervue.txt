Intervue Codebase Architecture and Product Flow

1. Product Summary

Intervue is a session-based, voice-first mock interview application with:

- a Next.js frontend in `frontend/src/app`
- an Express + TypeScript backend in `backend/src`
- MongoDB persistence for sessions and uploaded resume data

The app lets a candidate configure a role-focused interview, optionally attach a resume, answer questions by speaking into the browser, and review an evidence-based analytics report after the session.


2. Real User Flow

The implemented user journey is:

1. Land on `/`
2. Click through to `/setup`
3. Select a target role and experience level
4. Optionally upload a resume
5. Start a session through `POST /api/start-session`
6. Enter `/interview`
7. Hear the interviewer speak the current prompt
8. Record an answer with the microphone
9. Transcribe the answer through Deepgram
10. Analyze the answer and generate the next question
11. Repeat through the interview phases
12. Receive a short closing message
13. View the final report on `/analytics`


3. Frontend Pages

`frontend/src/app/page.tsx`
- Landing page
- Introduces the product and routes the user to `/setup`

`frontend/src/app/setup/page.tsx`
- Session setup page
- Collects:
  - target role
  - experience level
  - optional resume file
- Calls:
  - `POST /api/start-session`
  - `POST /api/upload-resume` when a file is attached
- Stores `sessionId`, `firstQuestion`, and `currentPhase` in `localStorage`

`frontend/src/app/interview/page.tsx`
- Live interview room
- Displays assistant and user messages
- Plays interviewer voice from `POST /api/voice/speak`
- Records candidate audio with `getUserMedia` + `MediaRecorder`
- Sends audio to `POST /api/transcribe`
- Sends answer analysis requests to `POST /api/analyze-response`
- Sends question-generation requests to `POST /api/next-question`
- Handles the closing flow with `POST /api/closing-message`

`frontend/src/app/analytics/page.tsx`
- Final analytics report page
- Loads report data from `GET /api/final-report?sessionId=...`
- Renders:
  - overall score
  - number of analyzed answers
  - completed phases
  - technical metrics
  - behavioral metrics
  - speaking evidence
  - strengths and weaknesses
  - recommendations
  - per-question review cards


4. Backend Entry and Routing

`backend/src/index.ts`
- loads environment variables
- connects to MongoDB
- mounts:
  - `/api` -> interview/session/report routes
  - `/api/transcribe` -> speech-to-text route
  - `/api/voice` -> text-to-speech route
- exposes `GET /api/health`


5. Session and Resume Storage

`backend/src/models/Session.ts`
- stores:
  - `sessionId`
  - `domain`
  - `experienceLevel`
  - `phase`
  - `questionIndex`
  - `history`
  - `evaluations`
- `history` contains assistant/user/system messages with timestamps
- `evaluations` stores answer-level scoring records used for the final report

`backend/src/models/Resume.ts`
- stores:
  - `sessionId`
  - original filename
  - extracted text
  - structured resume data


6. Interview Engine

The interview engine is split across:

- `backend/src/interview-engine/prompt-builder.ts`
- `backend/src/interview-engine/phase-controller.ts`
- `backend/src/services/gpt-service.ts`

6.1 Prompt builder

`prompt-builder.ts` creates the system prompt for the interviewer model using:

- selected domain
- current interview phase
- experience level
- recent history
- resume-derived skills/projects/experience when available

It also enforces these runtime rules:

- ask only one question at a time
- stay brief and conversational
- avoid filler openings such as "Alright" or "Great"
- behave like an interviewer, not a teaching assistant

6.2 Phase controller

`phase-controller.ts` advances the interview through six phases in this exact order:

1. `intro`
2. `resume`
3. `technical`
4. `behavioral`
5. `situational`
6. `closing`

Per-phase question limits in the current code:

- `intro`: 1
- `resume`: 3
- `technical`: 3
- `behavioral`: 2
- `situational`: 2
- `closing`: 1

6.3 LLM generation service

`gpt-service.ts` uses Groq with `llama-3.3-70b-versatile` to:

- generate the next interview question
- generate the short personalized closing message

It uses a system prompt plus the last few conversation messages and sanitizes filler-style openings before returning text to the frontend.


7. Resume Intelligence

`backend/src/services/resume-parser.ts`
- extracts text from uploaded resumes with `pdf-parse`
- sends the extracted text to Groq
- asks Groq to return structured JSON containing:
  - skills
  - projects
  - experience
  - education
  - summary

Important current-state note:

- the setup UI accepts `.pdf` and `.docx`
- the implemented parsing path is PDF-based
- documentation should therefore treat resume intelligence as PDF-backed in the current codebase


8. Voice Pipeline

The app is voice-first. The implemented voice pipeline is:

8.1 In the browser
- the frontend records audio with `MediaRecorder`
- the interview page tracks:
  - recording duration
  - answer-start latency after the prompt becomes available

8.2 Speech-to-text

`backend/src/routes/transcribe.ts`
- receives uploaded audio
- forwards it to Deepgram `nova-2`
- returns the transcript text

8.3 Text-to-speech

`backend/src/voice/voice.routes.ts`
`backend/src/voice/voice.controller.ts`
`backend/src/voice/tts.service.ts`

This layer:

- accepts interviewer text through `POST /api/voice/speak`
- synthesizes MP3 audio with `@andresaya/edge-tts`
- uses `en-US-JennyNeural`
- streams audio back to the client
- lightly rewrites/generated text for more natural spoken phrasing


9. Answer Analysis Engine

The answer analysis engine lives in `backend/src/analysis-engine`.

It runs after each candidate answer and saves a full evaluation record.

9.1 Technical evaluation

`evaluation.service.ts`
- uses Groq
- returns strict JSON with:
  - clarity
  - depth
  - relevance
  - structure
  - confidence
- also returns:
  - strengths
  - weaknesses
  - suggestions

9.2 Behavioral analysis

`behavioral.service.ts`
- uses Groq to score:
  - leadership
  - ownership
  - problem solving
  - communication
- then calibrates those scores using evidence heuristics from the actual answer text so weak evidence does not get inflated

9.3 Coaching note generation

Also in `behavioral.service.ts`
- creates one short improvement tip per answer

9.4 Speech analysis

`speech.service.ts`
- does not use an LLM
- computes:
  - latency
  - speech rate
  - filler word count
  - confidence signal


10. Final Report Engine

`backend/src/analysis-engine/scoring.service.ts`
- aggregates all saved evaluation records into a final session report

The returned report contains:

- `overall_score`
- `interview_count`
- `completed_phases`
- averaged technical metrics
- averaged behavioral metrics
- averaged speech metrics
- repeated strengths
- repeated weaknesses
- recommendations
- per-question review data
- technical evidence summary
- speaking evidence summary

Current scoring weights:

- 65% technical metrics
- 25% behavioral metrics
- 10% speaking metrics when available

The analytics UI in `frontend/src/app/analytics/page.tsx` renders this report directly.

12. Environment and Runtime Requirements

Backend environment variables:

- `PORT`
- `MONGODB_URI`
- `GROQ_API_KEY`
- `DEEPGRAM_API_KEY`

Frontend environment variables:

- `NEXT_PUBLIC_BACKEND_URL`

Operational requirements:

- MongoDB must be available
- Groq must be configured for question generation, resume structuring, evaluation, and closing messages
- Deepgram must be configured for transcription during live voice interviews


13. What the App Is and Is Not

What it is:

- a live, session-based mock interview simulator
- voice-first
- role-aware
- phase-driven
- resume-aware when a PDF resume is provided
- report-driven after each session

What it is not in the current codebase:

- not a video interview platform
- not an authenticated multi-user SaaS app
- not a historical dashboard with cross-session accounts
- not a generic chatbot


14. Practical Mental Model

The easiest accurate mental model is:

- the frontend is the interview room
- MongoDB is the memory
- the interview engine decides what to ask next
- the analysis engine scores what was said
- the voice pipeline makes the interviewer speak
- the analytics page turns saved evidence into a final report
